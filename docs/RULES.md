# 房间规则与协议

## 游玩规则

- 最多 7 人，每场 20 手，初始 1000 筹码，盲注 10/20。筹码仅用于本场游戏。
- 首手由所有在线且有筹码的参与者准备后开始；游戏中加入的玩家先旁观，在两手之间选择“下一手加入”。至少需要一名准备好且有筹码的真人，机器人不会自行开一整桌。
- 两人桌庄家兼小盲，翻牌前先行动、翻牌后后行动。多人人数变化时庄家按下一个有资格入局的实际座位移动；这是固定盲注朋友桌，不实现淘汰赛死庄或盲注升级。
- 服务端按待行动玩家和未补齐下注推进；完整加注才重新开放已行动者的加注权，累计短码全下达到完整加注量也可重新开放。无可继续下注的双方时，自动发完公共牌并比牌。
- 界面输入“本轮总下注到多少”，同时标注本次需支付的筹码。短码可以全下，不能用普通加注绕过最低加注额。
- 未跟注的多余投入退回；每个主池/边池独立判定。平局的零头从庄家左侧首位获胜者开始分配。结算不增发或丢失筹码。
- 参与比牌者亮出全部底牌、最佳五张牌及牌型；弃牌者保持隐藏。全部对手弃牌时，胜者不强制公开底牌。自己始终可以看自己的底牌。
- 每手结果保留至在线参与者全部确认，机器人立即确认。第 20 手确认后进入比赛总结，在线成员确认总结后由房主重新开始。
- 操作上限 120 秒；超时或轮到已断线玩家时，能过牌就过牌，否则弃牌。断线全下手牌仍参加比牌。断线者不阻塞确认，座位保留 5 分钟。
- 主动离开立即释放身份；若当手尚未结束，保留投入和全下资格至结算。离席者仍纳入本场总结；房主离开/断线后转给下一位在线真人。
- 真人输完筹码可在两手之间重购 1000；重购累计计入总买入。盈利为剩余筹码减总买入。

下注重开、边池及零头分配参考 [Poker TDA 2026](https://www.pokertda.com/view-poker-tda-rules/)。本项目不是赛事裁判系统。

## Socket.IO v2

所有命令携带 `{ protocolVersion: 2, requestId: string, ... }` 并通过 callback 返回 `{ success, message? }`。同一身份最近 128 个请求按 ID 去重；超时重试使用同一个 ID。

- `createRoom / joinRoom / quickJoin`：昵称 1–16 字符；加入指定房间需六位十六进制房间号。成功返回稳定 `playerId`、`sessionToken` 和房间/座位。
- `rejoinRoom`：使用随机 `sessionToken` 恢复原座位，不使用昵称认证。令牌只通过自己的回调返回，禁止写入日志和公开状态。同一会话只允许一个连接。
- `leaveRoom`：显式离开。`ready` 接收布尔值 `ready`。
- `action`：携带 `handId`、`turnId`、`action`；`raise.amount` 为高于桌面当前下注的增量，与前端展示的加注总额不同。金额必须是安全整数。旧轮次、错误玩家、非法金额或终局动作均拒绝。
- `confirmNext / confirmSettlement`：携带当前 `handId`。`rebuy` 仅可在两手之间执行；`restart` 仅房主在总结全员确认后执行。
- `addBot`：`difficulty: easy|medium|hard`，`style: steady|balanced|active`；与 `removeBot` 都仅允许房主在手间执行。
- `chat`：1–60 字符，按普通文本显示。

`gameState` 包含 `youId`、`hostPlayerId`、`handId`、`revision`、`turnId`、合法动作及加注范围、机器人标识、结果和确认列表。暗牌在服务端过滤，不能依赖 CSS 隐藏。

## 部署与恢复

`/healthz` 返回服务状态与协议版本。生产以单实例运行：房间和会话保存在内存中，不支持多实例无共享状态，也不支持服务重启后恢复正在进行的比赛。发布应安排在无进行中牌局时；新协议上线需刷新旧页面，保留昵称，重新创建或加入房间。

先验证 PR，再沿用 Railway 发布流程；回滚可回到上一部署。回滚或重启同样会结束内存房间。不要将源码分支推送成功当成生产发布完成。

`node_modules` 已停止纳入版本控制；依赖通过锁文件和 `npm ci` 重建。`qs` 的 6.16.2 override 修复 Express 4.x 锁定旧传递依赖留下的已知漏洞。
